EVOLVE RF / Public Beta

A distributed RF-observability system built around evidence, uncertainty, and cooperative sensing.

EVOLVE RF is an experimental platform direction for turning observations from heterogeneous RF-capable devices into persistent events, cross-device correlation, candidate localization, and operator-facing evidence. This public Beta shows the system concept and current software evidence without publishing the proprietary RF Core.

The problem

Useful RF evidence is often scattered across devices, measurement types, clock qualities, and locations.

One observation is not the same thing as one RF event.

EVOLVE separates device-level observations from the higher-level event being investigated. That distinction matters because multiple sensors may see the same RF behavior with different timing quality, signal fidelity, location context, and measurement capability.

Core rule: a device owns an observation. EVOLVE owns the event.

The platform direction is to preserve each observation's provenance, qualify what each node is actually capable of measuring, and combine compatible evidence without pretending all sensors are equivalent.

System flow

Edge observations become persistent correlated events only after capability, timing, and provenance checks.

The software treats clock quality and measurement capability as part of the evidence.

01
Observe
A device reports a capability-bounded observation with timing, signal, and provenance information.
02
Detect
Local observations are compared with adaptive baselines and grouped into local events when warranted.
03
Correlate
Compatible observations from multiple devices are associated into a persistent cross-device RF event.
04
Locate carefully
RSSI, TDoA, AoA, or hybrid methods are considered only when the node capabilities and clock quality justify them. Every estimate carries uncertainty.
05
Cooperate
A fusion service may request additional sensing from eligible edge nodes, with command provenance and human/policy authority preserved.

Current software evidence

The private Alpha.4 build establishes a software baseline, not a production field-performance claim.

The current build proves software behaviors that can be tested locally and deterministically.

Authenticated transportHMAC envelope verification, freshness, payload integrity, replay/nonce, sequence checks, receipts, and edge/fusion delivery.
Event lifecyclePersistent correlation, inactivity, closure, resolution, recurrence, merge, split, and immutable event journaling.
Localization disciplineProbabilistic RSSI estimate with explicit uncertainty plus readiness boundaries for TDoA, AoA, and hybrid approaches.
Cooperative sensingCommand dispatch, acknowledgment, result return, and linked-observation provenance between fusion and eligible edge nodes.
Verification baseline

The Alpha.4 build manifest records 69 passing automated tests, an authenticated end-to-end demonstration, host validation output, OpenAPI contracts, a built Python wheel, an installed-wheel smoke test, and source/SHA-256 inventories.

What is not established

The Beta is intentionally explicit about what the current evidence does not prove.

Software readiness is not the same thing as RF field validation.

Not establishedProduction access to a specific commercial phone, router, modem, access point, SDR, chipset, driver, or firmware.
Not establishedField interference-detection sensitivity, false-alarm rate, classification accuracy, or calibrated cross-vendor RSSI equivalence.
Not establishedReal-world emitter-location accuracy or validated TDoA/AoA solver performance.
Not establishedProduction security certification, high-availability scale, fleet behavior, or autonomous mitigation authority.
Why it belongs here

EVOLVE RF extends the portfolio from one measurement workflow toward a multi-node RF system.

Cases 04 and 05 establish the instrument, agent, and RFML foundations. EVOLVE expands the question: how should multiple heterogeneous observations become one auditable RF event without losing timing quality, uncertainty, capability limits, or human authority?
